Step 1

LLM Quickstart

Configure Kong to act as your AI proxy. We will create an AI Provider definition, map a specific model, and test the connection.

1. Create AI Model Provider

Define the base provider (e.g., OpenAI) configuration.

kongctl apply generic-openai \
  --provider openai \
  --auth-header-name Authorization \
  --auth-header-value "Bearer $OPENAI_API_KEY"

2. Create AI Model

Map a specific endpoint and model to the provider created above.

kongctl apply my-gpt-4o \
  --provider generic-openai \
  --model-name gpt-4o \
  --route-path /v1/chat/completions

3. Validate the Connection

Send a standard prompt through your Kong Gateway.

curl -X POST http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      {
        "role": "user",
        "content": "Why is the sky blue?"
      }
    ]
  }'
Step 2

MCP Quickstart & Tool Mapping

The Model Context Protocol (MCP) standardizes how models connect to data and APIs. Here, we map an existing REST API to an MCP tool.

1. Map API to MCP Tools

Apply the ai-mcp-server plugin to teach the LLM how to format requests for your internal API (e.g., a customer data lookup).

curl -X POST http://localhost:8001/plugins \
  --header "Content-Type: application/json" \
  --data '{
    "name": "ai-mcp-server",
    "config": {
      "tools": [
        {
          "name": "get_customer_info",
          "description": "Fetch customer details by email address.",
          "route_url": "http://internal-api.local/customers",
          "method": "GET",
          "parameters": {
            "type": "object",
            "properties": {
              "email": {
                "type": "string",
                "description": "Customer email address"
              }
            },
            "required": ["email"]
          },
          "url_query_mapping": {
            "email": "email_query"
          }
        }
      ]
    }
  }'
Step 3

Get Started with AI Agent (A2A)

With tools mapped via MCP, you can now enable agentic behavior. The Kong AI Agent automatically intercepts tool calls from the LLM, executes the external API on its behalf (Agent-to-Agent/A2A), and returns the context.

1. Enable Agent Routing

Configure the ai-agent plugin on your route to orchestrate tool execution automatically.

curl -X POST http://localhost:8001/plugins \
  --header "Content-Type: application/json" \
  --data '{
    "name": "ai-agent",
    "config": {
      "auto_execute_tools": true,
      "max_tool_calls": 5,
      "system_prompt": "You are a helpful assistant. Use provided tools if necessary to answer user queries."
    }
  }'
How A2A Works in Kong: When a user asks "What is alice@example.com's order status?", the LLM attempts to use the get_customer_info tool. Kong intercepts this request, queries your internal API directly, and feeds the response back to the LLM to formulate the final answer—all in a single round-trip from the client's perspective.
Step 4

Rate Limit AI Traffic

Limit traffic based on AI token consumption rather than simple HTTP request counts. This is crucial for protecting against runaway A2A loops or expensive LLM prompt abuse.

1. Apply Advanced AI Rate Limiting

Add the ai-rate-limiting-advanced plugin. Here we limit consumers to 10,000 total tokens per minute.

curl -X POST http://localhost:8001/plugins \
  --header "Content-Type: application/json" \
  --data '{
    "name": "ai-rate-limiting-advanced",
    "config": {
      "limit": [10000],
      "window_size": [60],
      "identifier": "ip",
      "strategy": "local",
      "tokens_count_strategy": "total_tokens"
    }
  }'
Step 5

Monetize AI LLM Traffic

To monetize your AI APIs, you need precise metering. The AI Gateway parses responses from LLM providers to extract token counts and model information, which can be captured via telemetry and logs.

1. Enable Telemetry for Metering

By enabling standard logging plugins (like http-log), Kong automatically embeds AI usage metrics (prompt tokens, completion tokens, cost) which can be routed to your billing or analytics systems.

curl -X POST http://localhost:8001/plugins \
  --header "Content-Type: application/json" \
  --data '{
    "name": "http-log",
    "config": {
      "http_endpoint": "https://billing.internal/metering/webhooks",
      "method": "POST",
      "custom_fields_by_lua": {
        "ai_metrics": "return kong.log.serialize().ai"
      }
    }
  }'
