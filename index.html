Module 1

Introduction & Base Setup

Welcome to the Kong AI Gateway 2.0 Workshop! This interactive guide will walk you through transforming your API infrastructure into a powerful, intelligent, and secure AI Gateway.

Important: We will configure the base Service and Route only once here. All subsequent modules will apply plugins to this shared infrastructure to build up our AI capabilities.

1. Define the Upstream Service

First, we define a dummy upstream service. Since the AI Gateway intercepts the request and routes it to an LLM provider (like OpenAI or Cohere), this base service acts as a placeholder anchor in Kong.

curl -X POST http://localhost:8001/services \
  --data "name=ai-service" \
  --data "url=http://localhost:8080"

2. Create the AI Route

Next, we create a route named ai-route. Any HTTP request sent to our Kong Gateway that matches the path /v1/chat/completions will be handled by this route.

curl -X POST http://localhost:8001/services/ai-service/routes \
  --data "name=ai-route" \
  --data "paths[]=/v1/chat/completions"

🎉 Success! Your base infrastructure is ready. Let's move on to giving it AI superpowers.

Module 2

LLM Quickstart: The AI Proxy

The ai-proxy plugin is the heart of Kong AI Gateway. It allows you to route standard API requests seamlessly to multiple Large Language Models (LLMs) without changing your application code.

1. Configure the AI Proxy Plugin

We will attach the ai-proxy plugin to the ai-route we created in Module 1. In this example, we configure it to securely route traffic to OpenAI's gpt-4o-mini model.

Ensure you replace YOUR_OPENAI_API_KEY with a valid key.

curl -X POST http://localhost:8001/routes/ai-route/plugins \
  --header "Content-Type: application/json" \
  --data '{
    "name": "ai-proxy",
    "config": {
      "route_type": "llm/v1/chat",
      "auth": {
        "header_name": "Authorization",
        "header_value": "Bearer YOUR_OPENAI_API_KEY"
      },
      "model": {
        "provider": "openai",
        "name": "gpt-4o-mini",
        "options": {
          "max_tokens": 512,
          "temperature": 0.7
        }
      }
    }
  }'

2. Test the Connection

Now, send a standard OpenAI-formatted chat request to your Kong Gateway (port 8000). Kong will intercept it, inject your API key, and route it to OpenAI.

curl -X POST http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      {
        "role": "user",
        "content": "What is the capital of France?"
      }
    ]
  }'
Module 3

MCP Quickstart & Tool Mapping

The Model Context Protocol (MCP) standardizes how AI models interact with data sources and tools. With Kong, you can use the ai-mcp-server plugin to securely map your existing REST APIs as tools that LLMs can understand and use.

1. Map an API to an MCP Tool

Let's expose a simple Weather API as an MCP tool to the LLM. We define the tool's schema so the LLM knows what parameters it requires.

curl -X POST http://localhost:8001/routes/ai-route/plugins \
  --header "Content-Type: application/json" \
  --data '{
    "name": "ai-mcp-server",
    "config": {
      "tools": [
        {
          "name": "get_current_weather",
          "description": "Get the current weather in a given location",
          "route_url": "http://api.weatherapi.com/v1/current.json",
          "method": "GET",
          "headers": {
             "key": "YOUR_WEATHER_API_KEY"
          },
          "parameters": {
            "type": "object",
            "properties": {
              "location": {
                "type": "string",
                "description": "The city name, e.g. San Francisco"
              }
            },
            "required": ["location"]
          },
          "url_query_mapping": {
            "location": "q"
          }
        }
      ]
    }
  }'

What just happened? We told Kong: "Create a tool called get_current_weather. When an LLM wants to use this tool, map its location parameter to the q query string parameter, inject our API key securely, and make a GET request to the Weather API."

Module 4

Getting Started with AI Agents (A2A)

While MCP maps APIs to tools, the ai-agent plugin allows Kong to orchestrate the conversation. Kong will autonomously detect when the LLM wants to use a tool, execute the API call on its behalf (A2A connectivity), and return the result to the LLM to generate a final answer.

1. Enable the AI Agent Plugin

We apply the AI Agent plugin to our route. It relies on the configurations we set in the ai-proxy (for the LLM) and ai-mcp-server (for the tools).

curl -X POST http://localhost:8001/routes/ai-route/plugins \
  --header "Content-Type: application/json" \
  --data '{
    "name": "ai-agent",
    "config": {
      "max_tool_calls": 3,
      "auto_execute_tools": true
    }
  }'

How it works:

  1. You ask: "Is it raining in London?" via your Kong endpoint.
  2. Kong passes this to the LLM.
  3. The LLM decides it needs the get_current_weather tool and returns a tool call request.
  4. Kong (AI Agent) intercepts this, sees auto_execute_tools: true, and executes the actual HTTP call to the Weather API.
  5. Kong feeds the API response back to the LLM.
  6. The LLM generates the final natural language answer and Kong sends it back to you.
Module 5

Rate Limit AI Traffic

AI models are expensive. Standard API rate limits restrict HTTP requests, but with LLMs, a single request could consume thousands of tokens. The ai-rate-limiting-advanced plugin lets you rate limit based on token consumption to control costs effectively.

1. Apply AI Rate Limiting

Let's configure a limit of 5,000 AI tokens per minute for any consumer hitting this route.

curl -X POST http://localhost:8001/routes/ai-route/plugins \
  --header "Content-Type: application/json" \
  --data '{
    "name": "ai-rate-limiting-advanced",
    "config": {
      "strategy": "local",
      "limit": [5000],
      "window_size": [60],
      "tokens_count_strategy": "total_tokens",
      "identifier": "ip"
    }
  }'
  • limit / window_size: Allows 5000 tokens every 60 seconds.
  • tokens_count_strategy: total_tokens means we are counting both prompt (input) and completion (output) tokens combined.
  • identifier: Limits are applied per client ip address.
Module 6

Monetize AI LLM Traffic

To monetize AI APIs, you need precise metering. The AI Gateway parses responses from LLM providers to extract token counts. By routing this telemetry to analytics platforms, you can build billing models (e.g., charge per 1k tokens).

1. Capture AI Metrics for Metering

You can use standard logging plugins combined with AI Gateway telemetry. For example, using the file-log or http-log plugin, Kong will automatically inject token usage metadata (like llm.usage.prompt_tokens) into the logs.

curl -X POST http://localhost:8001/routes/ai-route/plugins \
  --header "Content-Type: application/json" \
  --data '{
    "name": "http-log",
    "config": {
      "http_endpoint": "https://your-billing-system.com/webhooks/kong-logs",
      "method": "POST"
    }
  }'
