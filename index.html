Kong AI Gateway 2.0 Workshop


0. AI Gateway Quick Start

Welcome to the AI Gateway 2.0 Workshop. The fastest way to get started is by deploying a local data plane node via the setup script and configuring it using kongctl.

Prerequisites & Setup

  1. Export your Konnect Personal Access Token (PAT): 
    export KONNECT_TOKEN="<your-pat>"
  2. Run the automated installation script to spin up the data plane node and configure kongctl: 
    curl -Ls https://get.konghq.com/ai | bash -s -- -k $KONNECT_TOKEN
  3. Export the necessary environment variables provided by the script output: 
    export AI_GATEWAY_ID="<your-gateway-id>"
export KONNECT_PROXY_URL="<your-proxy-url>"
export OPENAI_API_KEY="<your-openai-key>"

Create AI Entities

In AI Gateway 2.0, infrastructure is decoupled. You first create an AI Model Provider, and then link an AI Model to it.

1. Create AI Model Provider:

kongctl apply -g $AI_GATEWAY_ID -f - <<EOF
type: AIModelProvider
name: generic-openai
provider_type: openai
auth_credentials:
  type: API_KEY
  api_key: \${OPENAI_API_KEY}
EOF

2. Create AI Model:

kongctl apply -g $AI_GATEWAY_ID -f - <<EOF
type: AIModel
name: my-gpt-4o
provider_name: generic-openai
model_name: gpt-4o
EOF

Validation

Verify that your proxy routes traffic to the specific AI Model entity.

curl -X POST \${KONNECT_PROXY_URL}/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      {
        "role": "user",
        "content": "What is Kong API Gateway?"
      }
    ]
  }'

1. Konnect UI: Core Setup

Alternatively, you can manage your AI infrastructure visually via the Konnect dashboard.

  1. Log in to your Kong Konnect account at cloud.konghq.com.
  2. From the left navigation menu, click AI Gateway and select New AI Gateway to initialize your control plane. Name it appropriately.
  3. Navigate to AI Model Providers. Click New Provider.
    • Set name to generic-openai.
    • Select OpenAI as the provider.
    • Input your OpenAI API key securely and click Save.
  4. Navigate to AI Models. Click New Model.
    • Set name to my-gpt-4o.
    • Link it to the generic-openai provider.
    • Set upstream model to gpt-4o and click Save.
Crucial Note on Policies: In Kong AI Gateway 2.0, governance capabilities (formerly plugins) are called Policies, and they are strictly attached to the AI Model entity, not to a route.

2. Apply Key Auth Policy

To secure your AI Models from unauthorized access, attach the Key Authentication policy directly to your AI Model.

Configuration Steps

  1. In Konnect, navigate to AI Models and select my-gpt-4o.
  2. Click the Policies tab for this model.
  3. Click Add Policy, search for Key Authentication, and enable it.
  4. Leave the default setting (Header name: apikey) and click Save.
  5. Create a Consumer named ai-developer in Konnect, navigate to its Credentials, and generate a new API Key.

Validation

curl -X POST \${KONNECT_PROXY_URL}/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "apikey: <YOUR_API_KEY>" \
  -d '{
    "messages": [{"role": "user", "content": "Hello!"}]
  }'

3. AI Rate Limiting Policy

Control costs by limiting LLM usage based on actual token consumption instead of HTTP requests.

Configuration Steps

  1. Select your AI Model (my-gpt-4o) and navigate to its Policies tab.
  2. Add the AI Rate Limiting Advanced policy.
  3. Set the Limit Type to Tokens.
  4. Configure the Limit to 5000 and the Window Size to 60 seconds.
  5. Click Save.

Validation

When exceeding 5000 tokens within 60 seconds, the AI Gateway intercepts the request and responds with a 429 error before it reaches OpenAI.

# Request exceeding the token limit
curl -v -X POST \${KONNECT_PROXY_URL}/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "apikey: <YOUR_API_KEY>" \
  -d '{
    "messages": [{"role": "user", "content": "Write a 10,000 word essay."}]
  }'

4. Semantic Prompt Guard Policy

Protect your models using natural language intent detection instead of rigid regex rules. This requires attaching the policy to the AI Model and configuring an Embeddings provider.

Configuration Steps

  1. On the Policies tab of your AI Model, add the AI Semantic Prompt Guard policy.
  2. Configure the Embeddings settings to point to your provider (e.g., text-embedding-3-small).
  3. Under Deny Topics, define descriptions in natural language. For example:
    • "Financial or investment advice"
    • "Hate speech or offensive language"
  4. Click Save. If a prompt's intent mathematically matches these topics, the AI Gateway blocks it.

5. Semantic Caching Policy

Reduce latency and LLM costs by serving cached responses when user prompts mean the same thing, even if phrased differently.

Configuration Steps

  1. On the Policies tab of your AI Model, add the AI Semantic Caching policy.
  2. Configure the embeddings model details as you did for Prompt Guard.
  3. Set the Distance Threshold to 0.15.
  4. Select a cache backend (e.g., in-memory or Redis) and click Save.

If a new prompt's vector is within a 0.15 distance from a previously cached prompt, the policy instantly serves the cached LLM response.

6. Semantic Routing Policy

Dynamically route requests to different underlying models based on the semantic intent of the user's prompt. You attach this policy to an overarching generic AI Model that acts as a router.

Configuration Steps

  1. Create three AI Models: a generic entry model (e.g., ai-router), an OpenAI model (gpt-4o), and a Mistral model (mistral-large).
  2. Attach the AI Semantic Routing policy to the ai-router AI Model.
  3. Configure the Embeddings block in the policy.
  4. Define the Routing Rules:
    • Rule 1 Intent: "Write software code or scripts" → Route to AI Model: gpt-4o.
    • Rule 2 Intent: "General conversation and answering questions" → Route to AI Model: mistral-large.
  5. Save the policy.

Validation

# This request will be routed to GPT-4o
curl -X POST \${KONNECT_PROXY_URL}/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "apikey: <YOUR_API_KEY>" \
  -d '{
    "messages": [{"role": "user", "content": "Write a Python script to sort an array."}]
  }'

7. Prompt Decorator Policy

Inject system instructions invisibly at the gateway layer. Attach this policy to your AI Model to standardize behavior.

  1. Add the AI Prompt Decorator policy to your AI Model.
  2. Set Role to system.
  3. Set Content to: You are a highly concise AI. Always answer in one sentence.
  4. Choose Prepend to inject this before user messages, then Save.

8. Prompt Template Policy

Enforce strict API contracts. Instead of accepting unstructured text, require structured JSON variables from the client.

  1. Add the AI Prompt Template policy to your AI Model.
  2. Create a template named translator using Mustache syntax:
    [{"role": "user", "content": "Translate to {{language}}: {{text}}"}]
  3. Set Allow Untemplated Requests to false to force structured input.

9. MCP Server Setup

The Model Context Protocol (MCP) standardizes how AI models access external data and tools. Kong AI Gateway acts as an MCP Server, translating natural language tool calls directly into HTTP requests to your backend APIs.

Configuration Steps

  1. Ensure you have a standard Kong Service pointing to a backend API (e.g., a Weather API).
  2. In Konnect, create a new MCP Server entity.
  3. Within the MCP Server configuration, define a Tool Mapping to connect the AI's natural language understanding to your API route.
  4. Example Tool Mapping (YAML representation): 
    tools:
  - name: get_current_weather
    description: "Get current weather for a location"
    route_name: weather-api-route
    schema:
      type: object
      properties:
        location:
          type: string
          description: "City and state, e.g. San Francisco, CA"
      required: ["location"]
  5. Attach the MCP Server to your AI Model.

Validation

Send a prompt asking for the weather. Include the tool description in your request. The AI Gateway intercepts the tool call, executes the HTTP request, and feeds the context back to the model.

curl -X POST \${KONNECT_PROXY_URL}/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "apikey: <YOUR_API_KEY>" \
  -d '{
    "messages": [
      {
        "role": "user",
        "content": "What is the weather like in New York today?"
      }
    ],
    "tools": [
       {"type": "function", "function": {"name": "get_current_weather"}}
    ]
  }'

10. Agent-to-Agent (A2A) Connectivity

For autonomous operations, AI Gateway 2.0 manages traffic between AI Agents using standard JSON-RPC payloads, providing routing, rewriting, authentication, and OpenTelemetry tracing.

Configuration Steps

  1. Create an AI Agent entity in Konnect. Give it a name (e.g., support-agent).
  2. Configure the Agent's routing to point to an underlying AI Model.
  3. Rewrite Agent Card URLs: If your agents exchange metadata (Cards), configure Kong to rewrite internal URLs to external gateway endpoints so agents can locate each other securely.
  4. Observability: Attach the OpenTelemetry policy to the AI Agent entity to trace JSON-RPC calls between agents in Datadog or Honeycomb.
  5. Security: Secure agent endpoints using the AI Auth Strategy (e.g., OpenID Connect) to ensure only authorized agents can communicate.

Testing with a Dummy Agent

You can run a local test agent using Docker to simulate JSON-RPC traffic.

# Run a dummy AI Agent
docker run -d --name dummy-agent \
  -e AGENT_NAME=support-agent \
  kong/ai-dummy-agent:latest

Proxy JSON-RPC traffic through the Gateway to the agent:

curl -X POST \${KONNECT_PROXY_URL}/rpc \
  -H "Content-Type: application/json" \
  -H "apikey: <YOUR_API_KEY>" \
  -d '{
    "jsonrpc": "2.0",
    "method": "agent.communicate",
    "params": {
      "agent_id": "support-agent",
      "message": "Escalating ticket #1234."
    },
    "id": 1
  }'
