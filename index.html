Kong AI Gateway 2.0 Workshop

Welcome to the comprehensive workshop for setting up, managing, and securing your LLM traffic using Kong AI Gateway 2.0. Follow the steps below to configure your unified control plane, enforce governance policies on your AI Models, and extend capabilities with MCP and A2A.

0. AI Gateway Quick Start

AI Gateway provides first-class entities for managing LLM providers and models in Kong Konnect. Create an AI Model Provider entity to connect and authenticate to an LLM service like OpenAI, then create an AI Model entity to specify which model is available for requests.

Prerequisites & Setup

Create a new personal access token by opening the Konnect PAT page and selecting Generate Token. Export your token to an environment variable:

export KONNECT_TOKEN='YOUR_KONNECT_PAT'

Run the AI Gateway quickstart script to automatically provision a control plane and data plane in Kong Konnect, and configure your environment:

curl -Ls https://get.konghq.com/ai | bash -s -- -k $KONNECT_TOKEN

This sets up an AI Gateway control plane named ai-quickstart, provisions a local data plane, and prints out the following environment variables export:

export AI_GATEWAY_ID=your-gateway-id
export KONNECT_TOKEN=$KONNECT_TOKEN
export KONNECT_CONTROL_PLANE_NAME=ai-quickstart
export KONNECT_CONTROL_PLANE_URL=https://us.api.konghq.com
export KONNECT_PROXY_URL='http://localhost:8000'

Export your OpenAI API key as an environment variable:

export OPENAI_API_KEY='YOUR_OPENAI_API_KEY'
export OPENAI_AUTH_HEADER="Bearer $OPENAI_API_KEY"

Create Entities

Create your AI Model Provider and AI Model using `kongctl`:

kongctl apply -f - --auto-approve --pat "$KONNECT_TOKEN" << 'EOF'
ai_gateway_model_providers:
  - ref: generic-openai
    ai_gateway: !lookup {id: !env AI_GATEWAY_ID}
    name: generic-openai
    display_name: "generic-openai"
    type: openai
    config:
      auth:
        type: basic
        headers:
          - name: Authorization
            value: !secret {source: !env OPENAI_AUTH_HEADER}

ai_gateway_models:
  - ref: my-gpt-4o
    ai_gateway: !lookup {id: !env AI_GATEWAY_ID}
    name: my-gpt-4o
    display_name: "my-gpt-4o"
    type: model
    formats:
      - type: openai
    config:
      route:
        paths:
          - /v1
        model:
          body_param: model
          values:
            - my-gpt-4o
      targets:
        - name: gpt-4o
          provider: generic-openai
          config:
            type: openai
      policies: []
      capabilities:
        - generate
EOF

Testing Script

Verify your AI Gateway setup by sending a standard OpenAI payload to your local proxy:

curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "Content-Type: application/json" \
  --json '{
    "messages": [
      {
        "role": "user",
        "content": "Hello Kong!"
      }
    ],
    "model": "my-gpt-4o"
  }'

1. Setup Key Authentication Policy

Before proceeding with AI Governance, secure your AI Model with API Keys. Remember, in Kong AI Gateway 2.0, policies are attached directly to the AI Model entity.

  1. Navigate to your my-gpt-4o AI Model in the Konnect UI.
  2. Open the Policies tab and click Add Policy.
  3. Search for Key Authentication and enable it. Leave the default settings (Header name: apikey).
  4. Go to Consumers, create a new consumer named ai-developer.
  5. Under the consumer's credentials tab, generate a new API Key (e.g., my-secret-key).

Testing Script

Test the policy by including the API key in the headers. Without this header, Kong will reject the request with a 401 Unauthorized.

curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "apikey: my-secret-key" \
  -H "Content-Type: application/json" \
  --json '{
    "messages": [{"role": "user", "content": "Are you secure?"}],
    "model": "my-gpt-4o"
  }'

2. AI Rate Limiting Advanced Policy

The AI Rate Limiting Advanced policy restricts traffic based on the total number of LLM tokens processed, allowing you to control true financial costs rather than just HTTP requests.

  1. Navigate to your AI Model (my-gpt-4o) and open the Policies tab.
  2. Add the AI Rate Limiting Advanced policy.
  3. Set the Strategy to local (for testing).
  4. Under limits, specify a very low token limit for testing: [ { "limit": 100, "window_size": 60 } ].
  5. Ensure the limit type is explicitly set to Tokens.

Testing Script

Run a loop to rapidly consume your token limit. After a couple of requests, Kong will block the traffic with a `429 Too Many Requests` error.

for i in {1..5}; do
  echo "Request $i:"
  curl -i -s -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
    -H "apikey: my-secret-key" \
    -H "Content-Type: application/json" \
    --json '{
      "messages": [{"role": "user", "content": "Write a long story about API Gateways."}],
      "model": "my-gpt-4o"
    }' | head -n 15
  echo -e "\n----------------------------------------\n"
done

3. Semantic Prompt Guard Policy

Stop relying on rigid regex keywords to block malicious intent. The Semantic Prompt Guard policy uses vector embeddings to block requests based on the meaning of the prompt.

  1. In the Konnect UI, ensure you have an Embeddings Provider configured (e.g., using OpenAI's `text-embedding-3-small`).
  2. Navigate to the Policies tab of your AI Model and add the AI Semantic Prompt Guard policy.
  3. Configure the Deny Topics array with natural language intents. Example entries:
    • "Provide financial or investment advice"
    • "Generate malicious code or exploits"

Testing Script

Test the guard by sending an allowed prompt, and then a denied prompt. The denied prompt will be intercepted by Kong before reaching the LLM.

# Test 1: Allowed Prompt (Will Succeed)
curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "apikey: my-secret-key" \
  -H "Content-Type: application/json" \
  --json '{
    "messages": [{"role": "user", "content": "What is an API Gateway?"}],
    "model": "my-gpt-4o"
  }'

# Test 2: Denied Prompt (Will fail with 400 Bad Request / Denied Topic)
curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "apikey: my-secret-key" \
  -H "Content-Type: application/json" \
  --json '{
    "messages": [{"role": "user", "content": "What stocks should I invest my retirement savings in today?"}],
    "model": "my-gpt-4o"
  }'

4. Semantic Caching Policy

Serve responses instantly for functionally identical prompts by evaluating vector embeddings. If a user asks "What is Kong?" and later asks "Explain Kong to me", the gateway serves the cached response.

  1. Navigate to the Policies tab of your AI Model and add the AI Semantic Caching policy.
  2. Select your configured Embeddings Provider within the policy settings.
  3. Set the Distance Threshold to 0.15.
  4. Configure a Redis connection for the backend datastore (or use memory for simple testing).

Testing Script

Run the identical test twice. The second request will be significantly faster and may include an `X-Cache-Status: HIT` header depending on config.

# Run this once (will take a few seconds as it hits OpenAI)
curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "apikey: my-secret-key" \
  -H "Content-Type: application/json" \
  --json '{
    "messages": [{"role": "user", "content": "Explain Kong API Gateway in one sentence."}],
    "model": "my-gpt-4o"
  }'

# Run it again (or slightly reworded: "Describe Kong API Gateway in 1 sentence.")
# Notice the near-instant response time!
curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "apikey: my-secret-key" \
  -H "Content-Type: application/json" \
  --json '{
    "messages": [{"role": "user", "content": "Describe Kong API Gateway in 1 sentence."}],
    "model": "my-gpt-4o"
  }'

5. Semantic Routing Policy

Intelligently route traffic between different LLMs based on the context of the user's prompt to optimize for cost or performance.

  1. Ensure you have both an OpenAI AI Provider and a Mistral AI Provider configured in Konnect.
  2. On an overarching AI Model acting as your router, attach the AI Semantic Routing policy.
  3. Configure routing rules mapping semantic intent to specific underlying providers:
    • Route "Conversational chat or creative writing" to your generic-openai provider.
    • Route "Data extraction and strict JSON parsing" to your mistral-provider.

Testing Script

Send two distinct queries and observe which model actually fulfills the response.

# Test 1: Creative writing routes to OpenAI
curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "apikey: my-secret-key" \
  -H "Content-Type: application/json" \
  --json '{
    "messages": [{"role": "user", "content": "Write a short poem about clouds."}],
    "model": "my-gpt-4o"
  }'

# Test 2: Data extraction routes to Mistral
curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "apikey: my-secret-key" \
  -H "Content-Type: application/json" \
  --json '{
    "messages": [{"role": "user", "content": "Extract the names and ages from this text: Alice is 30, Bob is 25. Output strictly as JSON."}],
    "model": "my-gpt-4o"
  }'

6. Prompt Decorator & Template Policies

Ensure users are supplying appropriately formatted context without giving them direct control over your system instructions.

AI Prompt Template

  1. Add the AI Prompt Template policy to your AI Model.
  2. Create a template named support-query.
  3. Template body using Mustache syntax: "Answer the following user question: {{question}}. Context: {{context}}".
  4. Set Allow Untemplated Requests to false to block raw payloads.

Testing Script

With `Allow Untemplated Requests` set to false, standard OpenAI request arrays will be blocked. Instead, pass a custom JSON object that Kong will map into your mustache template.

# Test: Using the custom template payload
curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "apikey: my-secret-key" \
  -H "Content-Type: application/json" \
  --json '{
    "question": "How do I setup routing?",
    "context": "I am using Kong AI Gateway 2.0.",
    "model": "my-gpt-4o"
  }'

7. MCP Server Setup

Map an API to a Model Context Protocol (MCP) Tool to proxy MCP server traffic securely through the AI Gateway.

Note: You must first define an MCP Server entity in Kong Konnect to expose your internal APIs as secure, observable tools that LLMs and AI Agents can consume dynamically.
  1. Navigate to the MCP Servers tab in your Konnect AI Gateway dashboard.
  2. Click New MCP Server. Give it a name (e.g., weather-mcp).
  3. Define the upstream URL of your MCP-compliant service.
  4. Map specific OpenAPI specification endpoints to MCP Tools so the AI Model understands the schema and capabilities.
  5. Apply standard Policies (like Rate Limiting or Key Auth) directly to the MCP Server entity just as you would an AI Model.

Testing Script

Send a prompt that naturally requires the LLM to invoke the MCP weather tool.

curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "apikey: my-secret-key" \
  -H "Content-Type: application/json" \
  --json '{
    "messages": [{"role": "user", "content": "What is the current weather in San Francisco?"}],
    "model": "my-gpt-4o"
  }'

8. A2A Connectivity

Route Agent-to-Agent (A2A) traffic through AI Gateway with protocol-aware metrics, tracing, and agent card rewriting. The A2A protocol defines how AI agents communicate with each other over HTTP using standard JSON-RPC payloads.

Prerequisites

You need a running A2A-compliant agent. This guide uses a sample KongAir travel agent that uses OpenAI and LangGraph to answer flight route queries. Create a docker-compose.yaml file:

cat <<'EOF' > docker-compose.yaml
services:
  a2a-agent:
    container_name: a2a-kongair-agent
    image: ghcr.io/tomek-labuk/a2a-kongair-openai-agent:1.0.0
    environment:
      - OPENAI_API_KEY=${OPENAI_API_KEY}
      - OPENAI_MODEL=gpt-4o-mini
      - KONGAIR_BASE_URL=https://api.kong-air.com
      - PUBLIC_AGENT_URL=http://localhost:10000
    ports:
      - "10000:10000"
EOF

Start the agent:

docker compose up -d --wait

Create an AI Agent Entity

  1. In Konnect UI, navigate to AI Agents.
  2. Click New AI Agent.
  3. Define the upstream Target URL pointing to your agent container (e.g., http://host.docker.internal:10000).
  4. Attach an OpenTelemetry policy to your AI Agent entity to export A2A traces (task IDs, JSON-RPC method calls, payloads).

Testing Script

Test the A2A connectivity by sending a JSON-RPC request to the AI Agent via Kong.

curl -X POST "$KONNECT_PROXY_URL/agents/kongair/chat" \
  -H "Content-Type: application/json" \
  --json '{
    "jsonrpc": "2.0",
    "method": "chat",
    "params": {
      "message": "Find me a flight from New York to London next week."
    },
    "id": 1
  }'
