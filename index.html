Get started with AI Gateway

Register an LLM provider, publish a model under your own name, and send your first chat request through Kong. About 10 minutes, four commands.

Summary

AI Gateway has first-class entities for LLM providers and models. An AI Model Provider connects to and authenticates with a service such as OpenAI. An AI Model declares which model clients can call. In this guide you create both for OpenAI in Kong Konnect with kongctl, then proxy a request to OpenAI.

1 Prerequisites

AI Gateway running

This is a Konnect guide, so you need a Konnect personal access token.

  1. Open the Konnect token page and select Generate Token.
  2. Export the token: 
    export KONNECT_TOKEN='YOUR_KONNECT_PAT'
  3. Run the quickstart script. It provisions a control plane and a local data plane in Konnect and prepares your environment: 
    curl -Ls https://get.konghq.com/ai | bash -s -- -k $KONNECT_TOKEN

The script creates an AI Gateway control plane named ai-quickstart, starts a local data plane, and prints the exports below. Paste them into your terminal to configure the session.

export AI_GATEWAY_ID=your-gateway-id
export KONNECT_TOKEN=$KONNECT_TOKEN
export KONNECT_CONTROL_PLANE_NAME=ai-quickstart
export KONNECT_CONTROL_PLANE_URL=https://us.api.konghq.com
export KONNECT_PROXY_URL='http://localhost:8000'

kongctl v1.16.0 or later

You'll use kongctl to manage Konnect resources from the command line. Install it, and keep it current.

kongctl version

An OpenAI API key

  1. Create an OpenAI account.
  2. Create an API key.
  3. Export it: 
    export OPENAI_API_KEY='YOUR_OPENAI_API_KEY'

2 Create an AI Model Provider

The AI Model Provider defines how the gateway reaches OpenAI and stores the credentials it uses. First, build the authorization header value:

export OPENAI_AUTH_HEADER="Bearer $OPENAI_API_KEY"

Then apply the configuration with kongctl:

kongctl apply -f - --auto-approve --pat "$KONNECT_TOKEN" << 'EOF'
ai_gateway_model_providers:
  - ref: generic-openai
    ai_gateway: !lookup {id: !env AI_GATEWAY_ID}
    name: generic-openai
    display_name: "generic-openai"
    type: openai
    config:
      auth:
        type: basic
        headers:
        - name: Authorization
          value: !secret {source: !env OPENAI_AUTH_HEADER}
EOF

!env AI_GATEWAY_ID points at the gateway the quickstart script created, so this doesn't create a new one.

What each setting does

type: openai
The provider talks to OpenAI using OpenAI's standard API format.
name: generic-openai
A unique identifier. AI Models refer to this name to route requests through the provider.
config.auth
Stores your OpenAI API key. The gateway manages it securely and adds it to upstream requests, so clients don't have to send keys.

3 Create an AI Model

The AI Model declares which upstream models are available, how client requests are routed, and which provider serves them.

kongctl apply -f - --auto-approve --pat "$KONNECT_TOKEN" << 'EOF'
ai_gateway_models:
  - ref: my-gpt-4o
    ai_gateway: !lookup {id: !env AI_GATEWAY_ID}
    name: my-gpt-4o
    display_name: "my-gpt-4o"
    type: model
    formats:
      - type: openai
    config:
      route:
        paths:
          - /v1
        model:
          body_param: model
          values:
            - my-gpt-4o
    targets:
      - name: gpt-4o
        provider: generic-openai
        config:
          type: openai
    policies: []
    capabilities:
      - generate
EOF

As before, !env AI_GATEWAY_ID refers to the gateway from the quickstart script.

What each setting does

type: model
A synchronous model for request and response workloads.
name: my-gpt-4o
A unique identifier for this model.
formats
Declares that the model accepts OpenAI-compatible requests.
config.route.paths
Sets the base path /v1. Clients combine it with a capability path to form the full endpoint.
capabilities: [generate]
Turns on text generation, which adds a /chat/completions endpoint. With the base path, chat requests go to /v1/chat/completions.
config.route.model
Lets clients put my-gpt-4o in the request's model field instead of the upstream model name.
targets
Chooses where requests go. provider: generic-openai is the provider you created earlier, and name: gpt-4o is the OpenAI model called upstream.

4 Validate

Send a chat request through the gateway to confirm everything works:

curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
     --no-progress-meter --fail-with-body  \
     -H "Accept: application/json"\
     -H "Content-Type: application/json"\
     -H "Authorization: Bearer $OPENAI_API_KEY" \
     --json '{
       "messages": [
         {
           "role": "user",
           "content": "Say this is a test!"
         }
       ],
       "model": "my-gpt-4o"
     }'

A successful reply is an OpenAI-style chat completion. The request used the alias my-gpt-4o, and the gateway sent it to gpt-4o.

5 Clean up

Remove everything this guide created:

curl -Ls https://get.konghq.com/ai | bash -s -- -d
